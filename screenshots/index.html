    Screenshots¶

    Every section of every panel in the suite, one PNG each, cropped to the sidebar - 48 images across five products - plus the 24 surfaces that are not panels at all in popups/, and 19 operator dialogs in dialogs/.

    They are generated, not taken by hand. Regenerate the whole set after any panel change:

    # in Blender, with the suite installed and a scene open:
import importlib.util, sys
spec = importlib.util.spec_from_file_location(
    "rob_shots", "/path/to/repo/tools/shots.py")
m = importlib.util.module_from_spec(spec); sys.modules["rob_shots"] = m
spec.loader.exec_module(m)
m.run(out_dir="/tmp/shots_raw")

    # then, in a normal Python with Pillow:
python3 tools/crop_shots.py /tmp/shots_raw docs/screenshots

    Two steps because Blender's bundled Python has no Pillow: the capture has to happen inside Blender and the crop cannot, so the sidebar rectangle travels between them in crop.json.

    tools/shots.py finds the sections itself, from the registered *_show_* / *_open booleans, so a section added later is photographed without anyone remembering to add it here. It captures at 0.85 UI scale, because the sidebar width cannot be set from Python and at 1.0 several headers photograph truncated.

    The scene in the shots is ROB.blend. Anything showing real group names, map resolutions or file paths comes from that file.

    popups/¶

    The Baker's eleven per-map settings popovers, seven menus and six panel popups. None of these is a panel, so none of them appears in the set above, and between them they hold a good half of the Baker's map options.

    A popup is not always one picture. The High/Low Manager's floating panel draws whatever its inner tab is showing, so it is captured four times - High/ Low, Final, LOD and Shards - and the cluster popup is handed a real asset and one of its clusters, without which it draws nothing but its own heading.

    START WITH NO POPUPS ON SCREEN. Two runs in a row without clearing between them puts the second run's popups on the same grid spots as the first, with the same contents, and the difference is then literally nothing: the crop reports that half the set never opened.

    # in Blender, on a screen with no popups already open:
import importlib.util, sys
spec = importlib.util.spec_from_file_location(
    "rob_popups", "/path/to/repo/tools/popups.py")
m = importlib.util.module_from_spec(spec); sys.modules["rob_popups"] = m
spec.loader.exec_module(m)
m.run(out_dir="/tmp/popups_raw")     # 2 minutes; do not touch the mouse

    python3 tools/crop_popups.py /tmp/popups_raw docs/screenshots/popups

    Then click once in the viewport to clear the popups it leaves behind.

    A Blender popup cannot be closed from Python - not by moving the cursor, not by switching workspace, not by toggling the window's fullscreen. So the capture does not try: it opens each one somewhere different and takes the difference between consecutive shots, which is the popup that just opened, whatever is still sitting behind it. Anything that moves on screen while it runs ends up in a crop, which is why the mouse has to be left alone.

    One thing to know when reading these: a menu can draw differently depending on what is open elsewhere. The Baker's preset menu lists one preset fewer when the sidebar is closed than when it is open.

    dialogs/¶

    The confirm-and-options dialogs: Build Ladder, Prepare High Poly, the delete confirmations, the renames. Same capture, same crop - tools/popups.py holds their operator names in DIALOG_OPS and hands the ones that ask for it a real asset and part from the open file, without which they report '' not found and never open.

    SAVE THE FILE FIRST. These are the only surfaces here that do not go away when you click elsewhere - a props dialog wants OK or Escape - so with a stack of them on screen a click that lands on an OK button runs that operator for real, and several of these delete things. It happened on 8 Oct: clearing the screen after the capture ran one of the Copy to LOD0 dialogs and added 225 meshes to the scene. Capture on the repo's own Test Blends/ROB.blend, dismiss every dialog with Escape, and never save the file afterwards.

    dialog-robhl.part_rename.png is from the 13 Sep capture: it did not open in the 8 Oct one.

    Two of the twenty-two are not here, both for the same reason: their poll or their first check fails unless the scene is in a particular state, and putting it in that state to take a photograph would rewrite the file.

    preferences/¶

    level-manager.png is the one hand-taken shot: Preferences opens in a window of its own, which tools/shots.py does not drive. It was taken with bpy.ops.screen.screenshot_area overridden to that window (a screen= override is refused for its temporary screen), and the add-on's details rows were cut out because they show the install path on the capturing machine.
